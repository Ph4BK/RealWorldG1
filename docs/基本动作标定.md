## 命令

```bash
# 前进
python3 RealWorldG1/tools/calibrate_g1_motion.py --speed 0.2 --duration 2
# 后退
python3 RealWorldG1/tools/calibrate_g1_motion.py --speed -0.2 --duration 2
# 左转
python3 RealWorldG1/tools/calibrate_g1_motion.py --yaw-rate 0.15 --duration 2
# 右转
python3 RealWorldG1/tools/calibrate_g1_motion.py --yaw-rate -0.15 --duration 2
```

| 参数 | 单位/意义 | 要求 |
| --- | --- | --- |
| `--speed`（别名 `--vx`） | m/s；正前进、负后退 | 有限数，省略为 0 |
| `--lateral-speed`（别名 `--vy`） | m/s；机体横向速度，约定正左、负右 | 有限数，省略为 0 |
| `--yaw-rate`（别名 `--omega`） | rad/s；正左转、负右转，不是目标角度 | 有限数，省略为 0 |
| `--duration` | 请求持续时间，秒 | 有限正数 |

至少一个速度分量非零，时间须显式指定。没有应用层幅值或时长上限，
但不代表固件没有内部限制，或任意参数都安全有效。
支持前后与横向速度组合，不支持同时非零平移与转向。
正常完成不追加零速度，异常保留回退；不是急停工具。
普通动作成功时静默、不保存实验数据；成功退出码为 0，失败为非 0，并在 stderr 显示失败原因。
显式 `--odom` 查询仍输出查询结果；参数错误和 `--help` 仍显示用法。

## 横移与偏移补偿（待真机验证）

官方 `SetVelocity(vx, vy, omega, duration)` 接收三个速度分量；此前 vy 固定为 0，
现在可直接指定。横移不同于转向，不主动改变朝向。正负方向按机体坐标约定，
首次横移仍须现场核对本机响应。以下仅是参数用法示例，**不是已标定补偿值，运行即运动**：

```bash
# 前进时叠加向左横向速度：一条请求 velocity=[0.2, 0.02, 0]
python3 RealWorldG1/tools/calibrate_g1_motion.py --speed 0.2 --lateral-speed 0.02 --duration 2
```

仅指定 `--lateral-speed` 与 `--duration` 即纯横移；负值向右。
应先现场验证纯横移方向、响应和到期自停，再测试组合平移；
前进/后退/转向的既有验证不代表横移已验证。
固定前向速度与时长，对比 vy=0 及小幅正负 vy，测量稳定后真实侧移与朝向并重复。
若朝向变化、绳索牵引或地面条件导致偏移，恒定 vy 未必能消除它，不能直接用 odom
侧移除以时长得出补偿系数。

预览、`--execute`、`--log`、`--duration-only-test` 均已移除，
传入旧参数会报错而不会发送指令。普通动作不输出结果；只有 `--calibrate` 选项保存标定数据并输出文件路径；`--plot` 独立读取已有数据汇总绘图。
仅查看帮助可以使用 `--help`，不会执行动作。

## 标定方法

1. 固定地面、机器人模式和绳索支撑方式。吊装条件改变会影响位移，
   吊装标定不能直接等同于自由行走标定。
2. 从已测试的幅度开始：平移速度绝对值 0.2 m/s、转向角速度绝对值 0.15 rad/s。
   一次只改变速度或时间中的一个，勿突然大幅增加。
3. 标记开始位置与朝向。执行一次后，确认站稳再测量净距离或净转角。
   不用速度×时间或未经校验的 odom 作为真实物理位移。
4. 同一组参数重复测量，前后左右分别记录；人工干预、回退和未迈步样本单独处理。
5. 根据实测物理结果形成参数表，不预设线性响应。

可自行记录：动作、速度/角速度、时长、稳定后物理距离/转角、侧移、支撑条件、异常。
## 到期后参数标定（`--calibrate`）

先不加此选项，通过肉眼试选 `v` 和 `omega`。选定后，对前进、左转、右转分别重复实验。
以下仅为参数示例，**每条都会运动，不要批量运行**：

```bash
python3 RealWorldG1/tools/calibrate_g1_motion.py --speed 0.2 --duration 2 --calibrate
python3 RealWorldG1/tools/calibrate_g1_motion.py --yaw-rate 0.15 --duration 2 --calibrate
python3 RealWorldG1/tools/calibrate_g1_motion.py --yaw-rate -0.15 --duration 2 --calibrate
```

仍然只发一条带 duration 的非零速度指令，到期自行停止，不主动追加 StopMove。
只有异常才尝试原有零速度回退。`--calibrate` 仅支持前进、左转、右转，不与 `--odom` 混用。
底层 C++ 在同一会话中继续接收数据，Python 返回之后仅保存数据，不靠另起查询进程拼接。

前提：同一 DDS 域内已启动 FAST-LIO 和 PosNav 定位，`/g1/live_bev/robot` 持续发布新鲜的
map 系位姿；不是只开启 FAST-LIO。普通模式不依赖 PosNav，起步和异常保护仍使用 `/dog_odom`。
每次 `--calibrate` 只保存 JSON/CSV，不导入 matplotlib、不生成 PNG。
发运动指令前检查输出目录可写；matplotlib 仅供实验结束后的独立 `--plot` 模式使用。

每次保存到当前这份部署源码的 `RealWorldG1/calibration_results/<UTC时间_唯一后缀>/`：

| 文件 | 内容 |
| --- | --- |
| `result.json` | 动作种类、指令参数、0 s/2 s 的 map 系 x/y/yaw、余动、原始样本、插值依据与接收延迟 |
| `velocity.csv` | 到期后 0–2 s 的分段速度：map 系 vx/vy、平面速率、机头方向有符号速度、偏航角速度 |

计时零点是**本机调用官方 SetVelocity 的时刻 + 实际传入的 float32 duration**，
不是响应返回时刻，也不声称知道固件内部精确的到期时刻。
位姿按消息的源时间戳对齐；0 s 和 2 s 没有恰好对应消息时，用前后样本插值，
XY 线性插值、yaw 按最短角差插值，并保存两侧时间偏差。
图中速度来自相邻位姿差分除以源时间间隔，不读取 `/dog_odom` 的 twist，
也不按消息接收间隔计算；CSV 的 `t_s` 为区间中点，图上为各区间的平均速度。
输出只包含平面位姿；该 PosNav 话题的 z 是显示高度，不作为真实高度标定。

标定位姿的源时间年龄和接收新鲜度均要求不超过 0.5 s，插值或差分跨度不得超过 0.5 s。
重复时间戳不刷新有效期，时间戳倒退、非法位姿或数据缺失均不作为有效标定样本。
采集持续到收到源时间覆盖 2 s 的样本；考虑消息延迟，最多等到本机到期后 3 s，
这不是增加运动时长。异常实验不会输出有效参数结果；运动已尝试时保留零速度回退。

`result.json` 的 `residual` 字段：

- `forward_m`：2 s 与 0 s 的 XY 差沿 **0 s 机头方向** 投影；前进实验取其均值初选 `epsilon_stg`。
- `yaw_rad`：带符号的最短余转角，另有 `yaw_deg`。
- `yaw_along_command_rad`：余转角乘以指令转向符号；左右转分别统计均值，避免正负抵消，用于初选 `theta_tol`。
- `distance_xy_m`、`dx_map_m`、`dy_map_m`：便于复查的二维位移信息。

按实验约定将 2 s 视为已静止，程序不以速度阈值自动确认停稳，也不自动选择等待时间或写入控制参数。
通过曲线肉眼确定 `turn_settle_s` / `walk_settle_s`；若 2 s 末仍有明显运动，该次结果不能当作完整余动。
定位噪声、ICP 修正和人体摆动会进入位姿差分曲线，因此它不是独立测量的真实机体速度。
这些均值只是阈值初值，后续需在单次 STG 中检查实际停止效果；左右转不一致时保留两组结果。

旧 `odom_before` 动作输出和 `*_at_return_*` 字段均不再提供。普通模式不保留位姿序列或实验文件。
本次只修改标定工具，不实现 PosNav 自动运动闭环。

## 实验结束后汇总绘图（`--plot`）

在同一机载部署根目录运行下面的命令，**仅画图，不发送运动指令、不连接 ROS**：

```bash
python3 RealWorldG1/tools/calibrate_g1_motion.py --plot
```

默认递归扫描 `RealWorldG1/calibration_results/` 下的 `result.json`，从文件中的动作种类
统计前进、左转、右转各有多少次已保存的实验，不依赖聊天记录。普通模式或未保存成功的动作
不计入；同一文件不会因为重复选择目录而重复计入。缺失路径、空目录或损坏记录明确报错。
以前版本保存的 `result.json` 也可汇总；已有的单次 PNG 不删除，也不作为汇总输入。

可以只选择指定的实验目录、批次目录或 `result.json`，并指定输出位置：

```bash
python3 RealWorldG1/tools/calibrate_g1_motion.py --plot \
  RealWorldG1/calibration_results/<实验目录1> \
  RealWorldG1/calibration_results/<实验目录2> \
  --plot-output RealWorldG1/calibration_results/selected_summary.png
```

默认生成 `RealWorldG1/calibration_results/velocity_summary.png`，一张图三行两列：
三行分别为前进、左转、右转，两列分别为带符号前后方向速度（m/s，正值前进、负值后退）和带符号偏航角速度（rad/s）。
每次实验一条未经平滑的曲线，横轴统一为到期后 0–2 s，同次实验在两个子图中颜色相同。
图例标注实验编号、v、omega 和指令时长；同名 JSON 文件保存编号、动作、参数、原始结果文件
路径的对应表，终端输出各类实验次数和文件路径。无记录的动作显示 No experiments。
前后速度使用 `forward_m_s`：每个差分区间的 map 系速度沿区间中间机头方向投影，排除左右方向分量；不取绝对值，也不裁掉负值。
`epsilon_stg` 仍使用 0–2 s 净位移沿 0 s 固定机头方向的投影，不使用平面位移长度或仅累加正向运动。
选择等待时间关注脚步是否已停，不要求机身晃动完全消失；此位姿差分只是参考，不是脚部里程计。
不同指令参数保留为不同曲线，不自动求平均或选取阈值；原 CSV 中的平面速率仍保留作复查。
再次绘图覆盖指定的汇总输出，原始实验文件保持不变。
