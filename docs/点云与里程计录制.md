# G1 点云与雷达 IMU 录制

目的：为后续 FAST-LIO 输入适配与离线回放采集数据。
仅录制 `/utlidar/cloud_livox_mid360` 和 `/utlidar/imu_livox_mid360`；不再录制 `/dog_odom`。
录制脚本为 `record_g1_lidar_imu.sh`，名称与实际录制的点云及 IMU 话题一致。
这两个宇树话题并非仓库默认的 Livox CustomMsg 输入；是否可直接回放仍需验证格式、时间与外参。
程序只订阅保存，不切 FSM、不发送运动或停止指令。停止录制不会停止机器人。

## 在 PC2 手动开始与停止

```bash
cd /home/unitree/g1_posnav
bash RealWorldG1/tools/record_g1_lidar_imu.sh
```

无需手动进入 Docker。看到两个话题的订阅成功提示及 `Recording...` 后，
先保持静止约 5 秒供后续 IMU 初始化，再用遥控器在净空和现场保护下平移、转向；
结束时先用遥控器让机器人站稳约 3 秒，再在录制终端按一次 **Ctrl+C**。
等待回到 PC2 shell 提示符后再关闭 SSH，不要用断开 SSH 或强杀代替正常停止。
可先做几十秒短录制；不要假设 Ctrl+C 会控制机器人停下。

每次创建独立目录，不覆盖旧数据。启动时打印完整路径，例如：

```text
/home/unitree/g1_diagnostics/lidar_imu_YYYYMMDD_HHMMSS_XXXXXXXX/bag
```

`bag/` 中应有 `metadata.yaml` 和 `.db3` 数据文件。容器写入后，会在正常退出或 Ctrl+C 结束时
将本次输出目录的所有权交回启动脚本的用户，可直接删除。强杀或断电可能来不及执行此步骤。
后续传输整个 `bag/` 目录，不要只传 metadata。
启动失败可能留下空目录，不表示录制成功。
如需换存储位置，在脚本后提供输出父目录路径。

## 后续分析约定

只生成一张所有帧直接累计的 XY 投影，不做起点/中间/终点分别着色叠加。
原始点云叠加检查保留原始点坐标，不预先套用 odom 或安装外参；
可剔除零坐标等无效点，并明确说明过滤规则。
FAST-LIO 回放则另行处理时间同步、预处理及 IMU–雷达外参；不修改原始包。
