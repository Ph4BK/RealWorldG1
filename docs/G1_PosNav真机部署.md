## 2. 正式静态地图

本地地图包：`RealWorldG1/maps/full_lab_v1/`。

| 文件 | 用途 |
|---|---|
| `map.pcd` | 固定的三维参考地图，供启动及运行中的点云定位使用 |
| `bev_occupancy.npz` | 未膨胀的二维二值占据图，作为每次任务的静态底图 |
| `bev_config.json` | 高度、分辨率、原点、索引方式等参数 |
| `metadata.yaml`、`T_map_from_*.txt` | 地图元信息、初始 IMU 高度参考及坐标变换 |
| `package_manifest.json`、`checksums.sha256`、`provenance/` | 正式文件清单、完整性校验和构建依据 |

静态 BEV 在 `map` 坐标系内生成：高度闭区间 **0.05～1.3 m**、分辨率 **0.05 m/格**、每格点数 **≥ 2** 为障碍，其余为空闲。这里的 count 是最终 `map.pcd` 的投影点数，不是观测帧数。地图大小 204×204，XY 原点为 `[-1.7, -7.1] m`，索引为 `occ[row_y, col_x]`。

`bev_counts.npz`、预览 PNG 和构建中间点云不是运行依赖，不纳入正式包；计数与预览可从正式 PCD 按需重建。任务更新不覆盖磁盘静态地图。

## 3. 从传感器到任务地图

### 3.1 输入、坐标和启动定位

已有 FAST-LIO 提供 `/cloud_registered_1` 配准点云和 `/Odometry_loc` 里程计；初始化还读取 `/utlidar/imu_livox_mid360`。点云已处于 FAST-LIO 的 `camera_init` 世界系。

保持 G1 静止至少约 2 秒，在 RViz 的 **2D Pose Estimate** 中标出当前 **IMU 参考点** 的 map 系位置和朝向。箭头给出 x、y、yaw，IMU 静止加速度确定重力方向，z 取地图元数据参考值。粗定位变换为：

```text
T_map_odom = T_map_currentIMU × inverse(T_odom_currentIMU)
```

画箭头和点击 Start 时均检查输入新鲜度及静止条件；若画箭头后移动超过 0.05 m 或 3°，要求重新画箭头。点击 **Start Live Localization + BEV** 后才启动 `open3d_loc/global_localization_node`。该进程使用正式 PCD 做 ICP 定位；定位内部点云队列上限为 10，与 BEV 的 10 帧窗口是两个独立参数。

定位补丁在每次实际配准后发布 `/g1/localization_update`，包含扫描时间戳、fitness、accepted 和 `T_map_odom`。重复发送同一旧配准结果不会刷新有效期。地图节点接受满足要求的变换后，按时间戳关联点云与里程计：

```text
points_map = T_map_odom × points_camera_init
T_map_IMU = T_map_odom × T_odom_IMU
```

不再对已经位于 `camera_init` 的点云重复施加机器人位姿。每帧进入窗口时使用当时有效的定位变换投影为计数网格；历史帧保留已有计数，不随小幅定位修正重新投影。显著定位跳变会清空历史并重置任务地图。

### 3.2 最近 10 帧局部二值图

1. 取新的、有效且与里程计匹配的点云，变换至 `map`。
2. 保留有限坐标点，再筛选 `0.05 <= z <= 1.3 m`。
3. 使用静态 BEV 的同一原点、尺寸和分辨率投影；地图范围外的点丢弃，不扩展网格。
4. 每帧生成一个计数网格，保留最近 **10 帧**。累计计数 **≥ 2** 的格子为障碍，其余为空闲。
5. 窗口积满后，每收到一帧新的有效点云滚动更新一次，不是每 10 帧才更新一次。

实时 count 是窗口内累计点数，**不是至少两帧命中，也不是十帧多数投票**；同一帧的两个点就可以满足阈值。窗口不是点云去重后的计数。

点云实测约 10 Hz，因此 10 帧约覆盖最近 1 秒；窗口最大时间跨度设置为 2 秒，给时间抖动留出余量。缺失或全非法点云会暂停；一帧本身有效、但高度或范围筛选后无点，仍可作为全零计数帧参与窗口，这是“其余格子视为空闲”的实现语义。

### 3.3 圆形区域直接替换

以匹配当前点云的机体位置（采用 IMU 的 XY 位置作为参考点）为圆心，对栅格中心的平面距离判断：

- 平面距离闭区间 **0～2.0 m**，包括机体位置及其附近格子。
- 覆盖完整 **360°**，更新区域仅随机器人位置平移，与 yaw 无关。
- 仅距离大于 2.0 m 的区域不在本次覆盖范围内；没有内圈排除区。

令 `M0` 为静态底图，`Mt` 为任务地图，`Lt` 为最近 10 帧局部二值图，`Ut` 为当前圆形区域：

```text
任务开始：M = M0.copy()
每次有效更新：M[Ut] = Lt[Ut]
区域之外：保持上一次 M 的值
```

区域内既能新增障碍，也能清除旧障碍；不是与静态图做 OR。区域外保留此前更新，再次经过时继续覆盖。当前不额外做射线可见性判断或遮挡推理，区域内未达到 count 阈值的格子直接视为空闲。

更新区域由 `fastlio/config/live_bev.yaml` 中的 `update_radius_m: 2.0` 配置。首次清除仍需定位有效且积满 10 帧，并非点击 Start 后立即清空圆内地图。之后每次有效更新均覆盖整个圆内区域；近场有足够实时点数的格子仍保留为障碍。

FAST-LIO 的 `preprocess.blind` 已于 2026-10-12 从 0.5 m 调整为 **0.3 m**，是以雷达为原点的三维近距离点过滤。正式实时配置为 `fastlio/deploy/g1_live.yaml`，G1 容器加载 `/work/deploy/g1_live.yaml`；参数在进程启动时读取，修改后需重启 FAST-LIO，并重新初始化定位。BEV 覆盖区域不再排除近场：即使某格因近距离过滤或遮挡没有观测点，也按 count 阈值规则判为空闲。这不代表验证了该格可通行，也未新增完整身体/腿部分割或可见性推理。

地图更新模块输出未膨胀占据图。手动 FMM 预览在任务图副本上做规划用障碍膨胀，不回写静态图或任务图。

### 3.4 暂停、重置与生命周期

| 条件 | 行为 |
|---|---|
| 尚未积满 10 帧 | 收集窗口，不覆盖任务地图 |
| 点云/里程计断流、匹配失败、空/非法帧、定位失效或超时 | 清空窗口、暂停覆盖，保留任务地图；恢复后重新累计 |
| 重复帧时间戳 | 不重复计入窗口 |
| 里程计时钟回退 | 重置并要求重新初始化，避免沿用错误时间关系 |
| 接受的定位修正跳变超过 0.25 m 或 10° | 恢复静态底图，清空窗口和待处理队列 |
| Stop Localization + Updates | 停止所属定位子进程，暂停更新，保留当前任务图供观察 |
| Restore Static Task Map | 恢复静态底图并清空窗口；定位运行时重新收集 |
| 重新 Start 或重启程序 | 从静态底图开始新会话，不恢复上次任务修改 |

正式参数入口是 `fastlio/config/live_bev.yaml`。有效性阈值：传感器超时 1 s、窗口跨度 2 s、ICP 超时 6 s、accepted 且 fitness ≥ 0.7、点云/里程计时间差 ≤ 0.03 s。当前 `cloud_stamp_offset_s=0`，机载实测两者对应时间戳一致。不要通过随意放宽容差掩盖时间错位。

**2026-10-13 代码核对：地图更新频率与时间限制。**任务地图不是固定 10 Hz 定时发布：处理定时器周期为 0.05 s（20 Hz），每次处理待处理点云；窗口积满后，每个有效新点云触发一次融合并发布标准任务地图。正常点云约 10 Hz 时，地图更新约 10 Hz；第 7 节记录的最近一次现场复测为 9.60 Hz，并非本次重新实测。RViz 地图图形的 5 Hz 上限只影响显示。

| 配置或代码常量 | 当前值 | 实际用途 |
|---|---|---|
| `sensor_timeout_s` | 1.0 s | 运行时点云或里程计接收间隔超过此值，暂停更新；待处理点云源时间落后最新里程计超过此值也丢弃并暂停。启动时还检查 IMU 接收时间 |
| `registration_timeout_s` | 6.0 s | ICP 结果距原接收时间超过此值，或其源时间落后最新里程计超过此值，暂停更新 |
| `registration_odom_wait_s` | 1.0 s | ICP 结果领先已处理里程计时允许等待回调追上；超时拒绝该结果并暂停，详见第 3.5 节 |
| `max_window_age_s` | 2.0 s | 点云累计窗口的最大源时间跨度，超龄帧移出；相邻有效帧间隔超过此值则清空旧窗口重新累计，不是地图消息接收超时 |
| `pose_sync_tolerance_s` | 0.03 s | 点云与匹配里程计的最大源时间差；这是匹配容差，不是接收超时 |
| 点云等待里程计（代码常量） | 0.30 s | 点云暂时找不到满足匹配容差的里程计时等待；超过接收后 0.30 s 仍不匹配则丢弃该帧并暂停 |
| ICP 领先里程计容差（代码常量） | 0.20 s | ICP 源时间领先已处理里程计超过此值时进入有界等待，不立即拒绝 |

暂停更新会清空累计窗口并保留任务地图；普通输入故障恢复后须重新积满 `window_frames=10` 才再次融合更新。当前地图代码没有独立的“任务地图超过 X 秒未成功融合”配置。暂停时也可能发布保留的任务地图，且消息头使用发布时刻，因此不能仅凭地图消息刚收到或 header 时间较新就认定融合已恢复。2026-10-13 用户已确定第 9 节运控的判据：连续 1 s 没有成功融合更新即失效，下一次成功融合更新即恢复。任务地图 header.stamp 仅在成功融合时推进，初始/重置时为零；暂停重发保留地图时不推进该时间。

### 3.5 定位结果等待里程计回调（2026-10-12）

定位消息的 `stamp` 是配准使用的扫描时间；BEV 内部最新里程计时间是该节点已经执行回调的进度，不一定等于 FAST-LIO 已经发布的最新时间。现场约 148 秒只读观察捕获 7 次时间戳报错，但 59 次定位扫描时间均能对应到已发布的里程计。PosNav 容器在约 77% 的 CPU 配额周期内受到限流，BEV 输出位姿也出现滞后，证据指向回调积压导致原即时判断误报，而非已证实的传感器时钟跳变。

当定位结果领先于已处理里程计超过原有 **0.2 s** 容差，或尚无里程计时，先进入最多 10 条的等待队列，最长等待 `registration_odom_wait_s: 1.0` 秒。里程计回调及周期检查会自动重试；满足原有时间条件后即可接受，不需要等待下一次 ICP。等待期间不直接清空地图窗口，上一份定位结果仍受传感器、fitness 和 6 秒新鲜度检查约束；没有可用定位时不更新地图。

重复时间戳不会延长等待期限，延后接受也不会刷新原接收时间。超时或队列满才报告异常并暂停，后续有效定位可恢复；真正的里程计回退仍要求重新初始化。Stop、新会话、里程计回退及定位进程退出都会清空等待队列。此次没有放宽 0.2 s 判断或点云/里程计 0.03 s 匹配容差。

## 4. 可视化与接口

三个地图图层均为二值图，黑色障碍、白色空闲：

| RViz 图层 | 内容 | 标准数据话题 / 显示话题 |
|---|---|---|
| Original static BEV | 固定原始静态底图 | `/g1/bev/static` / `/g1/bev/static_display` |
| Last 10 frames local BEV | 当前窗口在圆形区域内的局部图，区域外透明 | `/g1/bev/local` / `/g1/bev/local_display` |
| Updated task BEV | 累计替换后的任务地图 | `/g1/bev/task` / `/g1/bev/task_display` |

建议每次只勾选一个地图图层，避免重叠。标准话题为 OccupancyGrid（占据 100、空闲 0，局部区域外 -1）；RViz 用 Marker/MarkerArray 渲染，避开软件 OpenGL 的标准 Map 着色器问题。不显示新增/清除障碍差异图层。

绿色初始箭头、蓝色当前位姿和圆形边界可独立勾选。两支箭头使用 Marker.ARROW；原 PoseStamped 话题 `/g1/live_bev/initial_arrow` 和 `/g1/live_bev/robot` 仍保留。这样避开已在真机 core dump 中定位到的 Humble PoseDisplay 取消勾选后崩溃路径。

目标位姿使用工具栏 **2D Goal Pose** 单独绘制，松开鼠标后显示红色箭头。输入话题为 `/g1/live_bev/goal_2d`，显示话题为 `/g1/live_bev/goal_display`，均与初始位姿分开。目标只记录 `map` 坐标系的 x、y（米）和 yaw（弧度），写入 `.cache/live_bev/goal_pose.json`；面板用角度显示 yaw。重画会覆盖上一目标。

画目标不需要定位已启动或传感器就绪，运行中也可重画；重画先停止当前导航，之后须用户点击 Start Navigation 才执行新目标，不修改初始位姿、定位进程及地图窗口。未画目标时 Start 正常使用，目标不是启动条件。Stop/Start 和恢复静态地图保留本次界面会话的目标；程序重启不自动载入旧目标，磁盘文件只保留最近一次记录。

服务为 `/g1/live_bev/start`、`stop`、`reset`；状态话题 `/g1/live_bev/status` 提供帧数、窗口大小、更新次数、fitness 等。面板帧数分母读取状态中的窗口大小。

RViz 渲染帧率设为 **10 FPS**。动态地图的 Marker/MarkerArray 图形由 `map_display_hz: 5.0` 限制为最多 **5 Hz**，仅在地图变化时生成，跳过中间显示快照、最终显示最新地图；停止、重置及异常清空立即刷新。地图融合、标准 OccupancyGrid 发布仍随有效点云更新，未降为 5 Hz；位姿话题及小型箭头/边界显示保持原流程。此次没有调整容器 CPU 配额。

状态话题新增 `pending_registrations`（当前等待条数）、`registration_deferred`（本会话累计进入等待的结果数）、`registration_wait_timeouts`（累计等待超时数），用于后续现场复测。

## 5. 真机部署结构

```text
电脑浏览器 127.0.0.1:6081
    │ SSH 本地端口转发（G1 SSH 端口 22）
    ▼
G1 192.168.123.164，宿主网络
    ├─ g1-fastlio-humble：传感器 → FAST-LIO → 点云、里程计
    └─ g1-posnav-humble：定位 + BEV + RViz
         └─ Xvfb/Mesa/Openbox → x11vnc :5901 → noVNC/websockify :6081
```

两个容器都使用 host 网络，ROS Humble/CycloneDDS，domain 0、eth0。DDS 消息在机载侧接收，不要求电脑运行 ROS。远程桌面两个端口仅监听 G1 的 `127.0.0.1`；电脑只需能 SSH 访问 G1、具备 SSH 客户端和浏览器。

PosNav 容器配置为 4 CPU 配额、8 GiB 内存、256 MiB shm，不设置开机自动启动。基础镜像、依赖、ARM/Open3D 适配及构建说明见 [机载环境说明](../posnav/README.md)。Mesa 使用 CPU 软件渲染；启动脚本移除基础镜像失效的 Tegra 动态库路径，再载入 ROS 环境；Python 优先使用配套的系统 NumPy/SciPy。

### 9.2 状态流程

```text
开始任务，读取有效定位、当前任务地图与目标 XY
    → 检查是否已进入最终目标 0.50 m 范围
    → 未到达：计算新的 STG，并检查本段可通行性
        → FMM 判定目标不可达，或选出的 STG 整段连线受阻：零速度等待，每隔 1 s 重试；成功后继续
    → 闭环转向 STG
    → 发送零速度，固定等待 turn_settle_s
    → 记录前进起点及固定参考线，闭环直走
    → 到达/越过本次 STG，或进入最终目标范围：发送零速度
    → 固定等待 walk_settle_s
    → 使用停稳后的最新位姿复核最终目标距离
        → 达标：结束任务
        → 未达标：根据最新实际位姿和任务地图重选 STG，重复
```

转向等待结束后、发出前进指令之前，也检查最终目标距离和本段输入有效性。已经进入目标范围时不再向 STG 前进。任务开始时已经满足位置容差则直接成功，不强制先执行一次 STG。

正常流程在任务开始或上一段完成后选择新 STG，本段执行期间保持 STG 固定。第 9.6 节规定的障碍等待 2 s 后仍受阻是例外：重新获取 STG，开始新的一步。前进过程中不通过转向或重规划修正横向偏移。现有手动规划预览仍是第 8 节所述功能，本节的自动执行流程已接入 Start Navigation / Stop Navigation。

### 9.3 闭环转向

当前 map 系位姿为 `(x, y, theta)`，本次 STG 为 `G=(gx, gy)`。每周期使用最新有效位姿计算：

```text
heading = atan2(gy - y, gx - x)
error = wrap(heading - theta)    # 归一化为最短转向角差
```

按进入转向阶段时的误差选择方向：

- `error > +0.12 rad`：选择左转，持续发送 `vx=0, vy=0, wz=+omega`；反馈误差到达或越过 `+0.12 rad`（`error <= +0.12`）时发送零速度。
- `error < -0.18 rad`：选择右转，持续发送 `vx=0, vy=0, wz=-omega`；反馈误差到达或越过 `-0.18 rad`（`error >= -0.18`）时发送零速度。
- 初始误差位于 `[-0.18, +0.12] rad`：无需转向，保持零速度，进入后续固定等待流程。

一次转向内方向固定，跨过停止阈值后结束转向，不因误差符号变化反向追赶。角差跨越 `±pi` 时须保持相邻反馈的角度连续性，不能把归一化跳变误认为越过停止阈值。停止后固定等待 `turn_settle_s`。第一版不采用比例角速度，也不在等待结束后加入额外的精调转向循环。

### 9.4 闭环前进与 STG 完成判据

转向停止并等待后，记录前进开始时的实际位置 `S`。固定本段 STG `G`，定义沿参考线的单位方向 `u`；机器人实时位置为 `P`：

```text
u = (G - S) / norm(G - S)
remaining = dot(G - P, u)
```

`remaining` 是沿参考方向的有符号剩余距离。持续发送 `vx=v, vy=0, wz=0`，每周期更新位置反馈；当 `remaining <= epsilon_stg` 时发送零速度。负值表示已经越过 STG 所在的垂线，同样结束本段，避免离散采样错过到达阈值后继续前进。

参考起点 `S` 和方向 `u` 在本段内保持不变，不随当前位置重建。若开始前已满足本段到达条件，则跳过前进，不对零长度向量归一化。

**不修正横向偏移，不设置横向偏移停止阈值，也不专门记录横向误差作为后续导航输入。** 下一段以最新实际位姿重新规划，上一段的横向偏移已包含在新的规划起点中，无需相对旧参考线单独补偿。该选择意味着本段完成只代表沿参考方向的进度达标，不要求进入 STG 周围的二维距离圆。

### 9.5 最终目标成功判据

最终目标 XY 为 `F`，使用二维欧氏距离 `norm(F - P) <= goal_xy_tol` 判断，与当前 STG 的投影完成判据分开。

前进中一旦进入最终目标 **0.50 m** 范围，即发送零速度并等待，无需继续走完当前 STG；停稳后再次检查，仍满足条件才返回成功，否则重新规划。目标 yaw 不影响这一判断。

0.50 m 恰好等于当前 STG 的基本步长，但二者是独立参数；STG 回退或接近目标时可能短于基本步长。现有 FMM 的距离停止、距离比停止或“未返回 STG”不能直接当作本版任务成功，必须独立检查最终目标欧氏距离；未达标且无法获得有效 STG 时保持停止并报告规划状态。

### 9.6 中断与实验顺序

**2026-10-13 用户确认的暂停、恢复和终止规则：**

- **地图失效：**连续 **1.0 s** 没有成功融合更新即判为失效，立即发送零速度，暂停并等待地图恢复；**下一次成功融合更新即恢复有效**，继续本步运控，不因地图暂时失效重新选择 STG。这里的更新指有效点云完成融合（`updates` 递增），即使占据格内容没有变化也计为更新；重发保留地图、显示刷新或恢复静态底图不计为融合更新。计时使用本机单调时钟；本会话尚无成功融合更新时地图无效。保留本步 STG、运动阶段、已选转向方向；已进入前进阶段时还须保留原参考起点 `S` 和方向 `u`。恢复前使用最新有效位姿复核目标距离、本段停止条件和通道，已经达到停止条件时进入结束等待，不再发送运动指令。地图恢复不覆盖位姿故障或用户取消等其他停止条件。
- **行走通道检查：**使用当前任务地图的膨胀结果（沿用第 8 节规划膨胀），检测从当前位置 `P` 指向本步 STG `G` 的连线上 **1 m 内**是否有障碍；STG 距离不足 1 m 时只检查至 STG。连线随当前位置更新，采用栅格 supercover 检查，不在已膨胀地图上额外增加通道宽度。通道检测方向与第 9.4 节固定的进度参考方向各司其职，不修改 `S` 或 `u`。本段开始前仍需检查最终所选 STG（包括规划回退点）的连线可通行性。
- **通道受阻：**发送零速度，等待 **2 s** 后用最新有效地图复查上述通道。障碍已移去则继续本步；仍有障碍则根据最新实际位姿和地图重新获取 STG，从转向阶段开始新的一步。若无法获得有效 STG，保持停止并报告规划状态。等待结束时地图仍无效则继续按地图失效规则保持停止，不能把无数据当成无障碍。
- **FMM 目标不可达：**若规划报告 `Goal is unreachable from the current position`，发送零速度并进入 `plan_wait`，保留当前任务和最终目标，不终止任务；面板继续显示该提示，并清除上一 STG 点。每隔 **1.0 s** 使用最新有效位姿和任务地图重新计算 STG，仍不可达则继续等待，获得有效 STG 后自动进入本步转向/前进流程，无需再次点击 Start Navigation。位姿或地图失效期间保持零速度、不执行重试；输入恢复且重试时间已到时立即尝试一次，不补跑错过的次数。等待期间取消或重画目标会结束任务。此重试也适用于下一条 STG 整段连线受阻；其他规划错误沿用原处理。
- **STG 整段连线受阻：**规划选出 STG 后，若开始转向前的整段连线检查失败，面板显示 `STG segment is blocked`，进入同一个 `plan_wait`，保持任务并发送零速度，每隔 **1.0 s** 使用最新有效位姿和地图重新计算 STG、重新检查整段连线，通过后自动继续。输入失效、取消和重画目标的处理与上述不可达等待相同。前进阶段的前方 1 m 通道检查及 2 s 障碍等待保持原规则。
- **取消与重画目标：**先停止并结束当前任务。重画目标不会自动启动运动，由用户显式启动新目标。
- **位姿故障：**运控层仅以本机接收时间检查 0.30 s 超时，不增加源时间戳过期、重复或倒退检查。故障时发送零速度并暂停，位姿恢复有效后继续本步；保留本步 STG、运动阶段、已选转向方向和前进参考 `S/u`，恢复前先复核到达条件及通道。地图和位姿必须同时有效，单项恢复不能覆盖另一项故障。此约定针对新增运控层；现有地图与定位模块的时间戳匹配、去重、回退检查仍按原逻辑执行，其要求重新初始化的故障不因运控接收超时解除而自动修复。

暂停与等待均采用计时状态，期间继续处理取消、目标变更和输入有效性。**2026-10-13 用户确认：不判断单段运动超时，不增加持续无进展判据，不增加控制循环卡住保护，不增加 watchdog。** 因而不设置对应超时、进度窗口或心跳参数；速度指令仍使用第 9.1 节已确定的 0.10 s 有效期。

实验依次验证：固定角速度转向及停止响应、固定速度直走及停止响应、单次 STG 的完整执行、连续 STG 与最终 0.50 m 到达判据。先确定控制参数和固定等待时间，再验收连续导航。所有位姿与到达误差均基于当前定位输出，不视为外部真值精度。
