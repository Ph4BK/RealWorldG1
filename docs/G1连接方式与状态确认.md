## 2. 网络拓扑

当前采用实验室局域网连接：

```text
Windows/WSL 开发机
  192.168.123.105（WLAN）
          │
          │ Wi-Fi
          ▼
实验室路由器/局域网
          │
          │ Ethernet
          ▼
G1 PC2：192.168.123.164/24
G1 PC1：192.168.123.161/24
```

G1 PC2 的 `eth0` 处于启用状态，`wlan0` 处于关闭状态。因此，“无线连接 G1”是指开发机通过 Wi-Fi 接入实验室局域网，再经路由器和网线访问 G1；G1 PC2 本身当前没有通过 Wi-Fi 联网。

地址角色：

- `192.168.123.161`：G1 运动控制计算机 PC1，主要提供 Unitree SDK2/DDS 运动与状态接口。
- `192.168.123.164`：G1 开发计算单元 PC2，用于登录、部署和运行用户程序。
- `192.168.123.105`：本次检查时 Windows 开发机的 WLAN 地址；该地址可能由 DHCP 动态分配，不应写死在程序中。

此前 WSL2 内部地址为 `172.23.62.106/20`，虚拟网关为 `172.23.48.1`。这是 WSL2/Hyper-V 的内部 NAT 网络，并非 G1 所在的物理局域网地址。

### 5.2 PC2 宿主 ROS 环境限制

已从经过构建验证的头文件确认 G1 高层 API：

| API ID | 方法 |
|---:|---|
| 7001 | `GetFsmId` |
| 7002 | `GetFsmMode` |
| 7003 | `GetBalanceMode` |
| 7004 | `GetSwingHeight` |
| 7005 | `GetStandHeight` |
| 7006 | `GetPhase`（deprecated） |
| 7101 | `SetFsmId` |
| 7102 | `SetBalanceMode` |
| 7103 | `SetSwingHeight` |
| 7104 | `SetStandHeight` |
| 7105 | `SetVelocity` |
| 7106 | `SetTaskId` |
| 7107 | `SetSpeedMode` |

`SetVelocity` 向 `/api/sport/request` 发送的参数结构为：

```json
{
  "velocity": [0.0, 0.0, 0.0],
  "duration": 1.0
}
```

其中三个速度分量依次为 `vx`、`vy`、`omega`。`StopMove()` 实现为零速度
`SetVelocity(0, 0, 0)`；普通 `Move` 默认持续 1 秒，continuous move 模式使用很长的
duration。G1 不能复用 Go2 的 API 1008 参数格式或 Go2 定时标定表。

## 7. 当前部署与接口

机载正式项目目录为 `/home/unitree/g1_posnav/RealWorldG1`；2026-10-20 已合并早期
独立运控部署内容。基础动作、标定和数据录制均从 `/home/unitree/g1_posnav` 运行。

- 基础动作与标定：Python `G1MotionExecutor` 调用官方 ROS 2 C++ `LocoClient`，
  使用速度和持续时间执行单次动作。用法见 [正式运控说明](../motion/README.md)。
- 连续导航：机载 Python 导航节点以 50 Hz 直接发布 API 7105 速度请求，每条有效期
  0.10 s，不等待响应；达到阈值、暂停或取消时主动发送零速度。
- PC2 与 PC1 通过 ROS 2/CycloneDDS 通信，不经 rosbridge；电脑用于远程操作与显示。
- 仅查询当前里程计可用 `python3 RealWorldG1/tools/calibrate_g1_motion.py --odom`，
  不发送运动请求；该命令不代替完整的运动模式检查。
- 点云与 IMU 录制见 [录制说明](点云与里程计录制.md)，导航及界面操作见
  [PosNav 部署说明](G1_PosNav真机部署.md)。

基础动作的响应等待策略与连续导航不同，不能互相套用。运行前仍由现场人员将机器人
切换到已验证模式，程序不自动切换。查询或响应成功本身不证明实际位移和停止精度。
